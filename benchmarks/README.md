# Performance evidence

The release decision uses real non-trivial inputs and public upstream APIs.
Timing values are medians of the raw series in `results/2026-08-02.txt`.
Compatibility was checked separately before timing, so a fast divergent result
cannot pass this gate.

## Full alignment and sequence workflows

`trim` reads and emits a 1,000 by 50,000 FASTA alignment. The rsomics maximum
gap fraction of 0.2 corresponds to trimAl `-gt 0.8`; both write FASTA to a
discarded stream. The distance fixture has 360 sequences of 8,000 sites.
Rsomics timing includes FASTA parsing, calculation, and labeled TSV formatting.
The scikit-bio timer starts after sequence construction and only accumulates a
checksum, which gives the oracle a conservative advantage.

| Operation | rsomics median | Oracle median | Throughput advantage |
|---|---:|---:|---:|
| Trim | 0.2710 s | 7.3948 s | 27.29× |
| Hamming | 0.0427 s | 0.7753 s | 18.14× |
| JC69 | 0.2622 s | 6.6344 s | 25.30× |
| K2P | 0.2560 s | 8.7155 s | 34.04× |

The K2P process used 13,975,552 bytes maximum RSS; the scikit-bio process used
166,969,344 bytes. Trimming used 184,926,208 bytes versus trimAl's 221,970,432
bytes.

## Inference cores

Both implementations receive the same 2,500-taxon Euclidean distance matrix
generated by the tracked 64-bit LCG. Matrix generation is outside the timing.
Rsomics uses compressed triangular storage for the evolving NJ matrix and
stores sorted neighbor identities as `u32` values.

| Operation | rsomics median | scikit-bio median | Throughput advantage |
|---|---:|---:|---:|
| Neighbor joining | 0.7798 s | 1.4673 s | 1.88× |
| UPGMA | 0.0597 s | 0.0612 s | 1.03× |

The process that runs both inference operations used 261,160,960 bytes maximum
RSS for rsomics and 304,693,248 bytes for scikit-bio.

## Tree cores

The two 4,000-tip trees are parsed before timing. RF-family and cophenetic
operations call the public library interfaces directly. Tip distance constructs
the complete 4,000 by 4,000 matrix.

| Operation | rsomics median | scikit-bio median | Throughput advantage |
|---|---:|---:|---:|
| RF | 0.0108 s | 0.0258 s | 2.38× |
| Weighted RF | 0.0262 s | 0.0304 s | 1.16× |
| Branch score | 0.0268 s | 0.0307 s | 1.15× |
| Cophenetic unit correlation | 0.1632 s | 0.3207 s | 1.96× |
| Tip-distance matrix | 0.0556 s | 0.0719 s | 1.29× |

The process running the five operations used 392,790,016 bytes maximum RSS for
rsomics and 803,454,976 bytes for scikit-bio.

## Tree measures and cospeciation

The measure profile computes Sackin, normalized Sackin, N-bar, Colless,
normalized Colless, B1, treeness, and gamma on the 4,000-tip tree. The Hommola
profile uses 150 hosts, 150 associates, 500 observed links, and 99
permutations. Rsomics timings include CLI input and output; the Python timers
start after parsed objects exist.

| Operation | rsomics median | Oracle median | Throughput advantage |
|---|---:|---:|---:|
| Eight tree measures | 0.0060 s | 0.0418 s | 6.91× |
| Hommola, 99 permutations | 0.0388 s | 0.3068 s | 7.91× |

Maximum RSS was 4,325,376 versus 169,803,776 bytes for the measure profile and
3,702,784 versus 198,426,624 bytes for Hommola.

```console
  cargo bench --bench inference

  tree-a-4000.nwk tree-b-4000.nwk --repetitions 9
```
